# CLAUDE.md

For an agent working **inside this repository** on the OCaml compiler or the
Rust runtime; modeler-facing guidance is `docs/agents.md`. Holds only what
cannot be derived by reading the code — the rest loads on demand, see
[Rules and skills](#rules-and-skills).

## Stakes

This software is used to inform major public health decisions. Errors in
inference, simulation, or data handling are not just bugs — they can mislead
policy. **A silent wrong answer is the worst outcome**, worse than a loud
failure and worse than being slow.

- **Correct before clean**: verify logic against the mathematical derivation or
  spec before refactoring for style.
- **Surface uncertainty.** If a change touches inference math or numerics and
  you are not certain it is correct, say so explicitly and propose the test that
  would settle it. "Plausible" is not "verified."
- The maintainer welcomes scrutiny over speed: a found bug or a flagged dubious
  design is more valuable than a fast green diff.
- **The compiler and tests are ground truth.** When unsure what a construct
  means, check the compiler, don't guess. A wrong guess must surface as a
  compile error or failing test — never as a silent change that looks plausible.
- **High-risk surfaces.** Changes touching `pgas.rs`, `pgas_grad.rs`,
  `obs_loglik.rs`, `obs_model.rs`, `if2.rs`, or `particle_filter.rs` are
  high-risk **regardless of how mechanical they look**. Read the full function
  before editing any part of it.

## The gate

The gate is tiered. Run the fast tier while iterating; the full `make test` (or
CI) is the authoritative gate before a change lands. CI mirrors every phase.

```bash
make test-fast        # inner loop: whole Rust workspace — NOT authoritative
make test             # authoritative, slow: every phase; mirrors CI
make test-ocaml       # OCaml compiler + dimcheck + IR round-trip
make test-rust        # Rust workspace except sim
make test-inference   # the sim crate (engine + inference stack)
make test-integration # cross-language CLI shell-out (slow)
```

**Never lower the bar to make something pass.** No `--no-verify`, no weakening
an assertion, no skipping a check, no widening a tolerance to get green. If
something fails, find the cause.

`cargo-nextest` is **not** used — its parallel launch burst wedges macOS
syspolicyd/code-signing; `cargo test` is sequential and safe. `sccache` is
optional (`brew install sccache`); the Makefile uses it only when on PATH.

## "camdlc version mismatch" is environmental, not your diff

`camdl` (the Rust runtime) refuses to run a `camdlc` (the OCaml compiler) whose
git hash differs from its own — an end-user safeguard against a drifted
runtime/compiler pair emitting/reading incompatible IR. The check is in
`rust/crates/cli/src/util.rs`: `find_camdlc` / `check_camdlc_version_once`.

**If you see `error: camdlc version mismatch` during a test run, it is almost
always environmental.** The `camdlc` on PATH (usually the shared
`~/.local/bin/camdlc`) goes stale whenever a parallel checkout runs
`make install` at a different commit. The message prints both hashes — check
them before suspecting your diff.

- **Gate with `make test`.** It handles the guard itself: `test-rust` prepends
  the freshly-built `camdlc` to PATH and skips the handshake, so `camdl` uses
  the compiler under test regardless of `~/.local/bin`. You do **not** need to
  install or sync camdlc first.
- **Ad-hoc `camdl <model>.camdl` runs:** set `CAMDL_SKIP_VERSION_CHECK=1`, or
  `CAMDLC=ocaml/_build/default/bin/camdlc.exe`.

Do **not**, to "fix" a mismatch red:

- `make install` / `make install-camdlc` — clobbers the shared
  `~/.local/bin/camdlc` that parallel checkouts rely on, causing false reds in
  _other_ worktrees.
- Pin via the `CAMDLC` env var in the test harness — it overrides the
  PATH-injected camdlc shims that `compile_once`/`ir_cache` install
  (`find_camdlc` priority 2 > 3) and breaks those tests; the harness uses
  PATH-prepend (priority 3) so a test's own shim still wins.

Full runbook: `docs/dev/testing.md` ("Gotcha: camdlc version check").

## Goldens and `ir/VERSION` are a human-loop change, never collateral

- **Stage goldens explicitly.** Never `git add -A` / `git commit -a` when golden
  or doc files are dirty — a formatter/editor that reformats `*.ir.json` or
  reflows markdown must not ride along in an unrelated commit. Review
  `git status` / `git diff --stat` before every commit.
- **A golden diff is reviewed by a human.** If a golden changed, that is the
  commit's subject, not a footnote. (Incident:
  `docs/dev/incidents/2026-06-09-golden-format-reverted-by-autoformat.md` — a
  docs commit silently re-pretty-printed 48 goldens; the CI check that would
  have caught it was masked for 4 days.)
- `ir/golden/` is a **separate frozen set**, NOT regenerated by
  `make update-golden` (gh#384).
- **An `ir/VERSION` bump, or an edit to `ocaml/lib/ir/` or
  `rust/crates/ir/src/`**, breaks every golden and requires the atomic
  OCaml+Rust+golden update — flag it and confirm before proceeding.

Mechanics: the `golden-update` skill.

## Markdown

Format any `.md` you touch with `mdfmt` (`dprint fmt`) as the last step.

**EXCEPTION: never run `mdfmt`/`dprint fmt` on `docs/camdl-language-spec.md`.**
It embeds ~30 `<!-- camdl-doctest-preamble -->` markers and fenced `camdl`
snippets that the doc-test harness parses; `dprint`'s reflow disturbs that
structure and turns passing doc-tests into failures/ICEs. Edit it by hand. Any
other `.md` with embedded doctest preambles is the same hazard — check before
formatting.

## Commits

**No AI/Claude trailers in commit messages — ever.** A commit message (and a
squash-merge body, which becomes one) must never contain `Claude-Session:`,
`Co-Authored-By: Claude…`, `Generated with Claude Code`, a `🤖` line, a
`claude.ai/code/session_…` URL, or any equivalent assistant attribution. This
applies to commits authored by agents too — strip the trailer before committing,
and when merging a PR whose commit/body carries one, rewrite the message clean
rather than landing it. The `commit-msg` hook
(`scripts/check_commit_trailers.sh`) rejects these; do not `--no-verify` past
it. Conventions: `docs/dev/commit-style.md`. Onboarding: `CONTRIBUTING.md`.

## Where work gets tracked

- `docs/dev/notes/` — dated design sketches, investigation logs.
- `docs/dev/incidents/` — serious bugs/outages: cause, fix, what it changes.
- `docs/dev/reviews/` — audits and PR write-ups (`Audit ref:` footer).
- `docs/dev/proposals/` — RFCs (`Proposal:` footer; follow exactly unless a
  deviation is documented inline). Normative docs: `docs/dev/` root.

Small, well-scoped work → a GitHub issue (`gh issue create`), referenced `gh#NN`
in the commit subject; no proposal needed. Bigger lifts (schema/IR changes, new
inference methods, anything cross-cutting) → a `docs/dev/proposals/` doc first.

## Releasing

**Publishing is maintainer-gated.** An agent may run `make release-suggest` /
`make release-prep` and draft notes; tagging and publishing are never an agent's
call. Runbook: the `releasing` skill.

## Debugging: use the channels that already exist

Check these before inventing new logging.

- `CAMDL_TRACE_STEPS=1` — one TSV row per substep to **stderr** from the
  chain-binomial backend (`t`, compartments, `flow_<name>`, `rate_<name>`,
  `total_pop`). Redirect stderr to a file; stdout carries the normal output.
  Also active in `intervention.rs` (logs intervention firings).
- `RUST_LOG=camdl_sim=debug` — inference diagnostics in `pgas.rs`,
  `particle_filter.rs`, `if2.rs` (-inf logliks, skipped observations, density
  mismatches).

## Alpha

The public surface is documented but breaking changes are still expected. Do not
add backwards-compatibility shims, `alias` attributes, fallback deserialization
paths, or deprecated field names. When a field is renamed, rename it everywhere
atomically. Policy: `VERSIONING.md`.

matching file: `dsl-surface.md`, `ir-schema.md`, `inference.md`,
`run-identity.md`, `rust-conventions.md`, `calendar-time.md`. Each carries that
area's required reading — read it before a structural change there.
